# План: полнотекстовые новости на своём сайте (легально, бесплатно)

## Цель
- Читать новость на своём сайте, а не уходить на чужой.
- Бесплатно и в легальном поле.
- На будущее: много источников → обработка → без дублей.

## Ключевой факт
Единственный бесплатный источник, легально отдающий **полный текст** статьи, —
**Guardian Open Platform** (`show-fields=body,bodyText`, 5000 запросов/день,
работает в проде, лицензия разрешает показ с атрибуцией). Он уже подключён,
но тело статьи не запрашивается и выбрасывается.

NewsAPI полный текст не даёт и в проде не работает → **убираем из фида.**
Русский язык сейчас не нужен → NewsAPI больше ничего не держит.

## Этап 1 — Guardian full-text (делаем сейчас)

Результат: новости открываются и читаются целиком на сайте.

1. **`lib/guardian.ts`**
   - В `fetchGuardian` и `searchGuardian` запрашивать
     `show-fields=thumbnail,byline,publication,trailText,bodyText`.
   - Маппинг:
     - `description` ← `fields.trailText` (сейчас `null`).
     - `content` ← `fields.bodyText` (полный текст, сейчас `null`).
   - `bodyText` — чистый текст с переносами абзацев, безопасен для текущего
     рендера `whitespace-pre-wrap` (без XSS, без санитайзера).

2. **Убрать NewsAPI из фида**
   - `app/page.tsx`, `app/category/[slug]/page.tsx`, `app/search/page.tsx`:
     перестать звать `fetchNewsAPI`/`searchNewsAPI`, оставить только Guardian.
   - `lib/mergeFeeds.ts` продолжает работать (на будущее для >1 источника).
   - Файл `lib/newsapi.ts` пока оставить в репо (не удалять), просто не вызывать —
     чтобы легко вернуть, если найдём легальный источник-аналог.
   - Убрать `NEXT_PUBLIC_NEWS_API_KEY` из обязательных (обновить `.env.local.example`).

3. **Проверка sync → БД**
   - Убедиться, что `syncArticlesToDb` кладёт `content` (bodyText) в Supabase,
     и что `/article/[id]` показывает полный текст (страница уже готова).

4. **Мелочь по безопасности**
   - Guardian-ключ стоит с префиксом `NEXT_PUBLIC_` — утекает в браузер, хотя
     фетч серверный. Переименовать в `GUARDIAN_API_KEY` (server-only).
     *(Опционально в рамках этапа 1 — согласовать с пользователем.)*

### Критерии проверки этапа 1
- `npm run build` без ошибок ✓
- Локально `/` показывает Guardian-новости с описанием ✓
- Клик по карточке → `/article/[id]` показывает **полный текст**, а не заглушку ✓
- Кнопка «Read full article on The Guardian →» остаётся (атрибуция) ✓
- Русский тумблер не роняет фид (Guardian для ru возвращает `[]` — фид пустой,
  это ожидаемо; при желании прячем переключатель ru — отдельно) ✓

## Этап 2 — пайплайн много-источник + дедуп (на будущее, итеративно)

Инфраструктура уже наполовину есть: таблица `articles`, sync-роут, дедуп по

Реальные кандидаты: издания с полнотекстовыми RSS и явным разрешением на
републикацию. Список нужно отдельно исследовать перед реализацией — не обещаю
заранее, что их будет много.
